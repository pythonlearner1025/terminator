# Resistance soldiers

`Soldier Template` is an authored Generator at `[34, 0, 9]`. Select it in the
stopped editor to inspect the model or change its `variant` parameter to `olive`
or `gray`. Its saved source is generated by `npm run scene`.

The model uses 17 named bones, rigid skinning, worn fatigues, a plate carrier,
magazine pouches, a radio, gloves, boots, a field cap and dust wrap. Its headlamp
is a short-range spotlight without a shadow map. Both guests share the body
geometry, lamp geometry, wear texture and reflection probe. Each variant has one
shared body material; skeletons belong to individual soldiers.

## View API

```js
import {PlayersView} from './lib/view/players.js'

const players = new PlayersView(viewer)
players.start(world, localPlayerId)
players.sync() // after the world or a received snapshot changes
players.stop() // safe to repeat; start also stops the previous session
```

`world.players` can be a `Map` or a plain object keyed by player ID. The view skips
the local ID, adds new teammates and removes departed teammates. It reads `pos`,
`yaw`, `pitch`, `crouch`, `moving`, `sprinting`, `weapon`, `firing`, `reloading`,
`hp`, `alive`, `downed` and `aim`/`aiming`. The core's `vel`, `activeWeapon`,
`reloadTimer`, weapon catalog rates and per-player shot events are supported too.
It does not change simulation state. Snapshot interpolation belongs to netcode.

States: idle breathing, walk, run, crouch, aim, fire recoil, reload, hit flinch,
death collapse and downed breathing. Analytic arm IK keeps the hands at the
weapon builder's grip anchors. The third-person adapter instantiates the existing
`WeaponView` builder once, shares its gun geometry and applies world PBR materials.
It hides the first-person hands and uses `UnitFx` from `lib/view/fx.js` for fire.
The supported weapons are pistol, M4, shotgun, plasma, knife and grenade.

The three-line GameManager hook is isolated in commit `3c54982`. Its
`mountPlayersView` helper synchronizes on render and reads the current local ID
through a callback, so the network integration can replace that callback.

## Showcase and reproduction

During Play, press **F10** to place two soldiers four metres in front of the
camera. Their ten states cycle every three seconds and weapons every six seconds.
Press **F10** again to remove them. The showcase uses its own small fake players
map, never the gameplay map. Its label stays inside the canvas pane.

Start the dedicated server without opening a browser:

```sh
npx kite3d dev --port 4580 --no-open --force
```

The capture harness reads the private connection copy at `.kite3d/w15-dev.json`.
If restarting this server, copy `.kite3d/dev.json` there locally without printing
its contents. Then run:

```sh
node docs/evidence/w15-soldier/capture.mjs
npx kite3d check
```

The harness uses headless Chrome, the installed Kite3D runtime, the saved scene,
and the real view modules. Its local HTML entry is supplied through a Playwright
route to avoid editor autosave conflicts in this shared working tree. Studio
lighting and camera framing are temporary showcase settings; the scene is never
saved by the harness. No desktop window is opened or focused.
